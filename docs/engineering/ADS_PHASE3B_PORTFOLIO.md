# Phase 3B: full-population portfolio analytics

Baseline 4de81f0 (Phase 3A). This read-only increment uses the same authorized, filtered, serializable canonical snapshot as Phase 3A. New GET /api/ads/canonical-portfolio requires adsreport_view, ASIN grouping, no entity drill; table pagination and sorting do not affect analysis. It is on-demand, with at most two concurrent portfolio requests per API process. No schema or financial writes.

## Concentration
For explicit total sales, attributed ad sales and ad spend, rank each seller/marketplace/currency/ASIN's net observed positive contribution by amount, then stable identity. Include the threshold-crossing product in the leading 80% bucket; remaining positives form the tail. Compute the threshold with exact integer cross multiplication, not a rounded percentage. The denominator is the sum of positive entity-level observed contributions, not signed portfolio net totals; show net, zero, negative, unknown and prior-only populations separately. Full and partial positive counts are explicit. No inference from absent facts, no mixing currencies, no claim that 20% of products necessarily drive 80%. Ten ranked examples; totals/counts reconcile to all entities. SQL materializes stable entity and rank cursors, pages 2,000 compact aggregate rows to the server; memory stays bounded by currency groups and sample size, not raw facts.

## Segmentation
One mutually exclusive class per authorized entity, including prior-only. Reference is weighted observed ad sales / spend across eligible entities (positive spend, nonnegative sales, compatible paired coverage, no negative net spend/sales/business revenue). Compare exact rational ratios by cross multiplication. Explicit zero-spend business sales require aligned spend/total sales; positive attributed sales with recorded zero spend is separate. Negative adjustments and incompatible coverage are not classified as efficient or inefficient. Partial observations are labelled; no profit, campaign, exposure or automated budget claims. Reference is relative to selected filters, not a target or Amazon recommendation. Counts reconcile with population; bounded examples ranked by positive spend, then business/prior sales.

## Trends
Shift prior dates forward by the equal period length and group them on the current calendar day, Monday-week or calendar-month boundaries; clip both slices to identical lengths. Show exact actual date ranges for both, including partial first/last buckets. All expected buckets are generated; missing current/prior observations remain null. Ratios are reaggregated from source totals and paired coverage, never averaged. Full period coverage still only describes stored records.

## Seller and brand comparison
Reaggregate from raw authorized scope, separated by currency and marketplace. Seller identity is persisted seller ID, brand is current unambiguous catalog metadata; absent/ambiguous brand is a real null group. Brand groups combine authorized sellers only within a marketplace/currency. Return top 20 groups per currency/dimension by observed current explicit total sales, nulls last, stable ties, prior-only groups represented. Report full group count; do not imply examples are exhaustive. Exact comparison metadata uses Phase 3A coverage guards.

Tests cover exact 80% boundary and crossing, zero/negative/missing populations, full-scope pagination independence, multiple currencies, complete/partial segmentation, aligned weekly/monthly windows, seller/brand aggregation, unauthorized scope and browser containment. No production DB access; performance under real report scale and production reconciliation remain release gates. Full UI redesign, export extensions, caching and deeper budget/target analysis remain later phases.
