# Phase 3A: exact comparisons and product review signals

Baseline main 02462ab. Phase 2B migration remains unchanged. This is the first analytics increment, not the entire Phase 3.

## Comparisons
Each canonical report returns per-currency current/prior comparison objects, and paginated entity rows include comparison metadata. Date windows remain equal length. Calendar coverage counts distinct stored fact dates; field coverage counts non-null values. A comparison is marked comparable only when both periods contain every calendar day and complete metric (or compatible ratio) coverage among stored rows. This does not prove that all catalog products or source reports were present. Missing values and days are not zero. Partial data can expose separately labelled observed deltas, never a complete-period growth claim. Percentage changes require a positive prior denominator. Ratio deltas use percentage points, multipliers or currency amounts. All subtraction and percent calculations use fixed-scale BigInt; no Number conversion of financial inputs. Attribution sales are not reconstructed into business revenue.

## Review signals
GET /api/ads/canonical-insights is authenticated and requires adsreport_view. It accepts the canonical report filter contract with ASIN grouping and no entity drill. It materializes the same authorized current/prior facts and catalog metadata as the report. SQL counts all matching entities and returns at most ten examples per currency and signal, ranked by the relevant observed spend, clicks or sales and stable owner/marketplace/entity keys. Currency groups are separate. Pagination and sort do not limit counts. Seven deterministic signals cover explicit zero-net-sales spend, zero-net-conversion clicks (default minimum 20), opposing spend/sales trends on complete observed periods, missing ad sales, incompatible TACoS coverage, and prior-only records. Signals can overlap; counts must not be summed as distinct affected products. Partial compatible observations are labelled, not treated as waste or a scaling instruction. No automatic budget changes, campaign/keyword data, profit claims, or AI calls. The 20-click review threshold is an engineering default, not statistical significance or an Amazon recommendation.

## Rollout and tests
No schema migration or production writes. Test exact arithmetic, positive baseline, sparse data, signed values, full-scope SQL counts, currency/owner isolation, previous-only rows, real SQL and API permissions. The UI loads review signals on demand so the heavier analysis does not run on every page load. Also harden the prior Phase 2B retry test: a due-time set to the current instant can round forward under datetime2(3); set its fixture one second in the past and assert claim success. Actual production retry cause was not independently observed. Add safe retry-code logging. Remaining Phase 3 work includes concentration/segmentation, daily comparative trends and deeper target and product drilldowns. Production report reconciliation is still required.

The workspace adds a currency-specific comparative metric table (CTR, CVR, CPC, CPM, ACoS, TACoS, ROAS, CPO, AOV and other source metrics), observed-only delta labels in product rows, and a currency/rule review panel. Review counts and samples retain the active date, seller, brand, category, currency and search filters, independent of table pagination/sorting. Clicking a review ASIN drills into its own stored seller and marketplace even when the primary table uses another grouping. Full visual redesign remains Phase 4.
