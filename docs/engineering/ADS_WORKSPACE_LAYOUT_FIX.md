# Ads workspace layout regression

Baseline main 52a3449 (Phase 2A). The canonical route had an inline display:grid with an implicit auto/min-content track, no width/min-width containment, and wide Ant tables. The shell hides overflow, so the workspace expanded to the right and controls and empty placeholders became inaccessible. The old ads.css was not imported by the canonical route. Use a dedicated bounded flex-column workspace, wrapping header/filter actions, separate capped-options note, explicit empty states, and width-bounded Ant table shells. Native table body/content owns horizontal scrolling; the first product column remains fixed with scoped stacking/background corrections for global Ant overrides. No change to global layout, other modules, report calculations, APIs or migrations.

Browser regression fixture mounts the actual routed Ads component with the production shell CSS and real providers, isolates unrelated navigation APIs, and mocks empty/populated/error responses. It checks right/left bounds, scroll widths, action visibility, large catalog labels and pinned-column behavior at desktop/tablet widths. Dedicated Ads CI runs these checks; it does not trigger OOS browser tests. Production browser acceptance still required.
