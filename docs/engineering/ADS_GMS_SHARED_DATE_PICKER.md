# Shared reporting calendar

Baseline fa6c95c (Phase 5A deployed per operator). GMS previously defined its Ant Design RangePicker and preset list directly in GmsReportToolbar. Extract the same component into common/ReportDateRangePicker.jsx and reuse it in both GMS and Ads. Preserve the GMS date format (DD MMM YYYY), six rolling presets, no-clear behavior, date input IDs, supported calendar and local start/end-of-day conversion. Ads no longer invokes the legacy global calendar from its report filter. Both pages update the existing DateRangeContext, so report/export/filter scope remains in sync with the header. Ads alone enforces the existing 366 inclusive day API limit and suppresses report/analysis requests for invalid global-header ranges. Clear non-date filters preserves the selected reporting period. Match the existing 32px Ads filter-control sizing and allow responsive wrapping. No global calendar rewrite or backend changes.

Regression coverage: Ads and GMS browser tests select shared presets and verify actual API request dates; Ads checks retained search, page reset, date persistence between views, budget scope and filter heights. Shared-component edits trigger both Ads and GMS phase-1 workflows. No production deployment performed.
