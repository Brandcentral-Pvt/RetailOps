# Automatic catalog ownership (Phase 2B.3)

New upload requests contain file and reportType only; no manual seller selection. Catalog lookup checks all ASIN mappings before applying user scope. Reject missing, shared/duplicate, unauthorized and unverified-context mappings; unlike GMS, canonical Ads facts require verified non-null seller and currency. Reject mixed currencies because the source has no currency field. All owners are shown in the validated preview, and persisted in AdsImportJobOwners for history access and filtering. Automatic job metadata is visible only to its original owner and, once mapped, only while every mapped seller is accessible. Invalid mapping results reveal no foreign seller IDs. Old explicitly scoped jobs retain their existing semantics. New clients cannot set a seller override.

The mapping hash covers sorted ASIN/seller/marketplace/currency entries. On confirmation the full source is revalidated, mapped again in the serializable writer transaction, compared with the verified snapshot, and all owners' locks are acquired. The entire file is written/reconciled atomically across sellers. Existing facts under a different owner/marketplace for the same ASIN/date reject the file; changed values also reject. No automatic catalog creation or historical replacement. Original file SHA and row numbers retained. Migration 103 makes job-only seller/context columns nullable; fact identity is unchanged. All API instances must upgrade together, and legacy pending jobs should drain before rollback. The new index supports cross-owner historical conflict checks.

Production data reconciliation remains required. This PR does not perform imports or touch the production DB.
