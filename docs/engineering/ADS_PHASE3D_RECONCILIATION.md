# Phase 3D: exact display and analytics reconciliation

Baseline main 1b1e686 (Phase 3C). PR #300 first introduces shared exact-string display formatting. Currency display has two decimals; INR and counts use Indian digit grouping; ratios use at most two decimals, preserve sign and distinguish unknown from zero. Integer counts strip SQL decimal padding; unexpected nonzero fractional counts are not silently truncated. BigInt string rounding avoids binary floating-point rounding and unsafe large integer conversion. This is presentation only: original stored values, metric calculations, filters, classifications, sorting, and Excel export payloads are unchanged. Full export redesign remains Phase 5.

## On-demand canonical reconciliation

GET /api/ads/canonical-reconciliation requires adsreport_view, strict seller scope, ASIN grouping and no entity drill. All checks use the same serializable materialized fact snapshot and current/prior windows as the canonical report; the existing catalog filter and marketplace/currency rules apply. One concurrent audit per API process, no automatic scans on initial load. No migrations or writes to persisted facts. Response is private/no-store. No per-product raw rows are returned. Results are PASSED, FAILED or NO DATA; at most 30 mismatch details per check, with full mismatch counts. Compare exact raw additive totals, non-null counts, ratio pair counts and paired numerator/denominator sums (not summed percentages). Nine checks cover ASIN rollup, fact identity, portfolio net/partition/reference, daily/weekly/monthly aligned raw and shaped trend output, full seller and brand aggregation before top-20 sampling, and explicit business alias equality. Date coverage is compared only across disjoint time partitions, not summed across product groups. Source-quality observations separately count missing/zero spend, missing ad sales, signed adjustments, unmatched catalog, attributed sales above business sales, and non-additive revenue/order rows. Attribution differences are informational, not failures; never force business totals to equal ad plus organic.

## Verification and limitations

Unit tests compare sub-cent and beyond-safe-integer values, null vs zero, missing populations and bounded failure detail. Disposable SQL tests run the actual CSV validator and writer, compare all mapped analytics metrics and populated counts with the source, exercise authorized multi-currency/previous-only sparse data, and deliberately inject an alias inconsistency outside the importer to ensure it is detected. The runtime audit is internal consistency of the selected stored facts, not proof that all advertising data was uploaded. Budget assessment and product benchmarks have their Phase 3C independent coverage/SQL tests; budget months use a different window and must not be equated to an arbitrary report range. No live database or original private report is committed or accessed.

Before calling Phase 3 production-certified: run the audit in the deployed workspace with the original report's date, seller, marketplace, currency; privately compare original CSV validation totals and field coverage with the canonical stored report under the same scope (include unchanged replay counts, do not assume all rows share the latest source hash); verify seller budgets separately against the configured calendar and coverage; record sanitized results. Compare GMS business data only where date basis, ownership, currency and coverage agree, never overwrite to force equality. A passing internal check does not establish complete source delivery. Performance at real multi-seller volume remains Phase 6. No data changes in this PR.
