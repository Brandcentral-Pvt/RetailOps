# Ads Phase 2B: durable background commit (first increment)

PR #294. Migration 101 upgrades the existing job table, without altering advertising facts or deleting prior history. Confirm now enqueues a READY job and returns HTTP 202; repeated confirms of active jobs are idempotent and a completed job returns its saved result. A user may close the modal and reopen history. Cancel is available before a worker claims the job, not while a transaction is in flight.

The primary worker polls SQL every three seconds, atomically claims an eligible queued or expired-lease job, and re-resolves the current active owner, credentials, role grants, exclusions and seller scope. It revalidates the exact source and checks catalog ownership using the existing canonical writer. A 180-second lease is renewed every 20 seconds and at actual stage boundaries; stale workers cannot publish facts because the terminal job update is token- and expiry-fenced inside the same SQL transaction. Three attempts max; transient failures retry after 15/30 seconds, while deterministic validation, ownership and financial conflicts fail closed. An explicit server pause stops new claims and fences completion; queued jobs retain their private payload until processed or cancelled. Preview expiry remains 24 hours for unconfirmed READY jobs; terminal outcomes clear staged bytes. The worker does not store or replay a user's session token.

Progress reports actual rows staged and stage labels; 100% staged is not success. The existing import size/data-row limits remain unchanged. Validation remains synchronous, error retention is still capped at 10,000 detected issues, and historical correction/replacement remains rejected. Full error streaming/retention, preview worker isolation, history filtering, throughput/load testing and actual production CSV reconciliation remain Phase 2B follow-up work.

Deployment: verify migration 101 and /api/health/ads-imports; ensure the primary worker starts. Deploy/restart all API instances together rather than mixing old synchronous confirmation and new queue code. Rollback requires draining or cancelling queued jobs and stopping workers first; the additive schema can remain, but the old app cannot interpret new states. No live database, report or deployment was accessed by this PR. Tests exercise queue idempotence, no synchronous writes, concurrent claims, recovery, lease fencing, revoked access, transient retry, cancellation, and real SQL fact/job atomicity. Browser tests cover polling, close while pending and the pinned product data row instead of Ant's hidden measurement row.
