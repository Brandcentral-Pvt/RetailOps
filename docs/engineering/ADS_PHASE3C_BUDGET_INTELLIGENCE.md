# Phase 3C: seller budget pacing and ASIN diagnostics

Baseline main aa7af8a (Phase 3B). Read-only, no schema or fact changes. Existing canonical-targets API remains compatible. New canonical-budget requires adsreport_view, the same strict seller scope, and only seller/date/currency filters.

Budget view uses each overlapping calendar month from its first day through min(selected end, previous completed UTC day), even if selected start is mid-month. The cutoff is explicit; it is not proof that the marketplace/report has closed. Future months have zero elapsed days and no actual claim. Configured monthly target takes precedence over yearly month allocation; duplicate same-priority targets remain conflicts. Seller context is verified with the existing mapping; mismatched historical contexts cannot receive a target or forecast. Show observed seller-month contexts without configured targets as well. Currency filter does not conceal context conflicts. Bound to 5,000 groups, no silent truncation.

Use configured weekly ADS spend allocations when all first four weeks exist, amounts are nonnegative and the exact sum reconciles with the monthly target. Weeks are 1-7, 8-14, 15-21, 22-28, 29-end. An omitted fifth week is unallocated zero only when preceding allocations sum exactly to the target. Prorate a partial week by its actual days with exact fixed-scale arithmetic; ignore generated legacy day rows because their seven-day generation can spill dates. Without a week schedule, provide an explicitly labelled linear calendar reference. Conflicting allocations suppress pace claims rather than guessing. Observed net spend and observed utilization are visible even when incomplete, but remaining budget, pace variance, linear month-end scenario and per-remaining-day ceiling require complete stored field/date coverage and no negative spend adjustments. Month-end scenario is arithmetic extrapolation, not a forecast guarantee. Zero budgets are valid; no divide by zero. No automatic changes to budgets. ACoS uses compatible observed numerator/denominator, lower is better, and exact comparison against configured percentage points; negative adjustments or incomplete coverage suppress target claims. Complete stored coverage is not proof of complete advertising reports.

ASIN drill-down returns product share of the full persisted seller/marketplace/currency portfolio, same current/prior dates; reference intentionally ignores product metadata/search filters. Preserve observed signed shares without clamping and label partial coverage. Compare weighted seller ratios to product ratios, no allocated ASIN budget or profit assumptions. Include observed positive-spend, explicit zero-net-sales, missing-sales, zero-conversion-click and signed-adjustment day counts, not campaign-level conclusions. All queries are owner-scoped and use the existing serializable report snapshot. Existing seller/parent drill behavior unchanged.

Phase 3B browser regression had a locator scoped to a parent inside its own descendant filter; correct the relative locator. This is a test defect, not proof of a production chart failure.

Production acceptance still requires live source reconciliation. No production access or writes. Phase 3D will reconcile all analytics and identify remaining accuracy/performance gaps before full UI redesign.

The page replaces the older seller-target table with a seller-month budget pacing table and detail modal, using only one automatic budget request. Filters expose observed above-budget, above-plan, ACoS above target, missing targets and data/plan gaps. Counts are group counts, not distinct seller totals. Each ASIN history drawer includes current/prior portfolio contributions, ratio reference gaps and daily review observations. Prior missing records stay empty. The budget/diagnostic display preserves exact numeric strings. ACoS direction is based on unrounded arithmetic while displayed ratio/gap values are rounded to six decimal places. Browser tests cover missing forecasts, status filters, details, owner identity and containment.
