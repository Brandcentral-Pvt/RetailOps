# Phase 2B release gates (automatic ownership, complete errors, cleanup, load)

Migrations 103 and 104 preserve all fact data and prior job history. New uploads auto-map ASINs across sellers and commit the complete report atomically. Legacy selected-seller jobs retain their previous semantics; new public uploads cannot specify sellerId. A shared ASIN, unknown mapping, unauthorized owner, different currency, historical owner conflict or changed mapping blocks the entire report. The source lacks account and currency metadata, so operator confirmation still asserts that the CSV is the correct report for its mapped accounts.

New parser attempts write every detected issue into compressed, bounded SQL chunks (1,000 issues per chunk) with backpressure. The published token becomes visible only on successful validation finalization. Retry or interrupted attempts never publish incomplete issues. The modal keeps the first 100. The error download builds the entire authorized report privately, verifies row counts, and serves XLSX up to 100,000 errors or full CSV above that count (no issue-count retention cap). Old truncated histories cannot be reconstructed; revalidate the original file to capture all errors. A fatal parse error can stop scanning; this is disclosed in the validation summary.

Retention policy: unconfirmed previews expire after 24 hours; confirmed queued work is not deleted on preview expiry. Terminal states clear source bytes. Detailed error downloads are retained for 90 days after completion; the job audit summary and mapped ownership remain. Unpublished chunks older than 24 hours are deleted in bounded sweeps. No financial fact or job-history deletion is scheduled. Cleanup runs with the existing primary worker.

CI includes isolated worker parsing and full disposable SQL Server validation/commit at 100,000 and 200,000 records, including exact sums, two mapped sellers and unchanged replay counts. These measurements are synthetic, not production capacity guarantees. The 32 MiB / 200,000 data-row source limits remain.

Production acceptance checklist: deploy all API instances together, check /api/health/ads-imports, verify primary-worker startup, upload the original CSV without seller selection, verify every ASIN has one authorized owner and consistent currency, confirm and wait for COMPLETED, compare its exact source/committed totals and inserted+unchanged count to validated rows, then replay unchanged data and verify zero new records. The canonical writer compares every typed source field under its transaction. Do not claim a live reconciliation until these results are observed. No production database access, customer data or original CSV is committed.

Rollback requires draining/cancelling queued jobs before deploying older code. Migration 103 adds an index to the canonical fact table; schedule deployment appropriately if that table is large. Review 90-day error retention with the business owner; this is a chosen operational default, not a user-specified compliance requirement.
